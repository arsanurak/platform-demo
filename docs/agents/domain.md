# Domain docs

This is a single-context repo.

## Read before exploring

- `CONTEXT.md` at the root: the glossary.
- `docs/adr/`: the decisions. Read any ADR that touches the area you are about to change.

## Use the glossary

Name things in issues, tests and code with the terms in `CONTEXT.md`, and avoid the synonyms it lists under _Avoid_. If you need a term that isn't there, either you are inventing language the repo doesn't use, or the glossary has a gap worth adding.

## Flag ADR conflicts

If a change contradicts an ADR, say so explicitly and propose a new ADR that supersedes it. Don't override it silently.
